PHYSICAL DEVICE TEST RESULT

Speech recognition is working.

Emmaus correctly transcribes what the user says.

The problem is that correctly recognized commands are NOT reliably being converted into actual Emmaus app actions.

Example physical-device test:

User says:

“Please read today’s Psalms Daily Devotional.”

Emmaus correctly recognizes/transcribes the request.

But instead of opening/resolving/reading the actual Psalms Daily Devotional, Emmaus generates a conversational response such as:

“While I'm not able to read the Psalms Daily Devotional aloud...”

That proves the failure is AFTER speech recognition.

The problem is:

TRANSCRIPT
→ INTENT
→ ACTION DISPATCH
→ ACTION EXECUTION

We need to repair that pipeline.

3. CENTRALIZE POST-TRANSCRIPTION DISPATCH
==================================================

There must be one authoritative decision point after a transcript is finalized.

Conceptually:

const intent = classifyVoiceIntent(transcript);

if (isDeterministicVoiceAction(intent)) {
    return executeVoiceAction(intent);
}

return handleConversationalRequest(...);

Do not implement this exact pseudocode blindly if an equivalent architecture already exists.

Reuse the existing architecture wherever possible.

The important rule is:

DETERMINISTIC COMMAND
→ EXECUTE APP ACTION

CONVERSATIONAL QUESTION
→ ASK EMMAUS

==================================================
5. CRITICAL FALLBACK RULE
==================================================

A deterministic command must NEVER silently fall through to conversational AI simply because execution failed.

For example:

intent = READ_DEVOTIONAL

but devotional resolver returns null

MUST NOT become:

Ask Emmaus:
“I cannot read the devotional aloud...”

Instead:

log:

[VOICE ACTION FAILED]

{
  transcript,
  intent,
  contentType,
  titleHint,
  resolverStage,
  failureReason
}

Then return a truthful operational response such as:

“I couldn't load today's Psalms devotional.”

This distinction is essential.

There are TWO different situations:

A. Emmaus does not understand the request.

B. Emmaus understands the action but cannot execute it.

Situation B is an engineering/execution failure and must NOT be disguised by an AI-generated conversational response.
