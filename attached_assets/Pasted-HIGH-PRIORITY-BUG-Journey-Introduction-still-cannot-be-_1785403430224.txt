HIGH-PRIORITY BUG: Journey Introduction still cannot be opened or edited.

Current published behaviour:

- Day 1 can be selected and edited successfully.
- Journey Introduction appears in the sidebar and progress list.
- There is no manual checkbox, which is correct.
- Clicking “Journey Introduction” does not open an editor.
- Clicking the green “Write Journey Introduction” button does nothing.
- Journey Introduction therefore cannot be written, saved or marked complete.

This confirms that Journey Introduction has only been added to the UI visually. It has not been connected to the same editor lifecycle that the daily content uses.

Do not redesign the screen again.

Fix the underlying implementation.

--------------------------------------------------
1. CREATE A REAL JOURNEY INTRODUCTION RECORD
--------------------------------------------------

Journey Introduction must be a real persisted content section associated with the journey.

It must not be:
- a visual-only progress item
- a disabled placeholder
- an ordinary numbered day
- an “Untitled Step”

Use a dedicated field or content record such as:

journey.introductionContent

or a structured section with:

type: "journey_introduction"

It must be stored permanently in the production database.

--------------------------------------------------
2. CONNECT BOTH ENTRY POINTS
--------------------------------------------------

Both of these controls must open the same dedicated editor:

- “Journey Introduction” in the left sidebar
- the green “Write Journey Introduction” button

They must set the editor state to Journey Introduction and display its editable form.

Do not merely select or highlight the item.

--------------------------------------------------
3. DEDICATED INTRODUCTION EDITOR
--------------------------------------------------

When Journey Introduction is selected, replace the Overview panel with:

Journey Introduction

[Large editable rich-text field]

Actions:

- Save Draft
- Save and Continue to Day 1

The editor must support:
- paragraphs
- line breaks
- italics
- basic formatting
- existing content loading when reopened

Do not show:
- Duration
- Journey Type
- the Overview form
- generic day fields such as Scripture, Prayer or Today’s Step
- Add Step
- Untitled Step

--------------------------------------------------
4. COMPLETION MUST BE DATA-DRIVEN
--------------------------------------------------

There must not be a manual checkbox.

Journey Introduction should automatically show as complete only when valid introduction content has been saved.

Completion rule:

trimmed introduction content is not empty
→ mark Journey Introduction complete
→ show the green completed indicator
→ unlock Day 1

If the saved introduction is later cleared, its completion state must update correctly.

Day 1 editing already works.

Investigate how Day 1:
- becomes selected
- loads its editor
- saves content

- unlocks the next item

Implement an equivalent lifecycle for Journey Introduction, while keeping it separate from the numbered day array.

Do not assign it day number 0 unless the existing data architecture absolutely requires that internally. It must never appear to the author or user as Day 0.

--------------------------------------------------

--------------------------------------------------

Trace and fix the actual click handlers for:

- Write Journey Introduction
