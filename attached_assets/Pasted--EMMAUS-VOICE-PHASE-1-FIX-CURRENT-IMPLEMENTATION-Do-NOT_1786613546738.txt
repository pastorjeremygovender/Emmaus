# EMMAUS VOICE PHASE 1 — FIX CURRENT IMPLEMENTATION

Do NOT rebuild Emmaus Voice.

Phase 1 has already been implemented. We are now testing the existing implementation and have found a specific failure.

CURRENT BEHAVIOUR:

* Microphone input works.
* User can speak to Emmaus.
* Speech is transcribed.
* Ask Emmaus receives the request.
* Ask Emmaus generates the correct TEXT response.
* However, Emmaus does NOT automatically SPEAK the response.
* On mobile, the "Hear Emmaus" control is not visible.

Therefore the speech-input → Ask Emmaus portion works.

The problem is the SPEECH OUTPUT / MOBILE UI portion.

Fix this existing implementation rather than creating another Voice system.

---

# 1. FIRST DIAGNOSE THE EXISTING CODE

Before changing anything, trace the complete existing VoiceMode pipeline:

microphone
→ recording
→ transcription
→ Ask Emmaus request
→ Ask Emmaus response
→ TTS request
→ audio response
→ audio playback

Determine exactly where the pipeline stops.

Specifically verify:

* whether VoiceMode knows when the Ask Emmaus response has completed
* whether the TTS endpoint is being called
* whether the returned response contains playable audio
* whether an Audio object/player is created
* whether playback is attempted
* whether mobile browser autoplay restrictions are preventing playback
* whether voiceEnabled gating is blocking TTS
* whether the selected voice/provider is correctly configured
* whether an exception is occurring silently
* whether the Hear Emmaus component is being hidden by responsive CSS or conditional rendering

Do NOT simply add another button to work around the problem.

Fix the underlying flow.

---

# 2. VOICE MODE MUST SPEAK AUTOMATICALLY

When the user enters Emmaus Voice Mode and speaks:

User speaks
→ transcription
→ Ask Emmaus
→ text response
→ Emmaus automatically speaks that response

The user should NOT need to press "Hear Emmaus" after every answer while in Voice Mode.

"Hear Emmaus" is the manual read-aloud control.

Voice Mode is conversational and therefore speech output should happen automatically.

Example:

User taps microphone and says:

"Who is Jesus?"

Emmaus generates the existing Ask Emmaus text response.

As soon as that response is ready:

Emmaus should automatically begin speaking it.

The text response should remain visible on screen while it is being spoken.

---

# 3. FIX MOBILE AUDIO PLAYBACK PROPERLY

This must work on MOBILE, not just desktop.

Investigate browser audio restrictions, particularly:

* iOS Safari
* Android Chrome

The initial user microphone/tap interaction should establish whatever user interaction/audio context is required for subsequent playback.

Do NOT depend on desktop autoplay behaviour.

Do NOT silently fail if autoplay is blocked.

If automatic playback is blocked by the browser, show an obvious fallback:

"Tap to hear Emmaus"

But first attempt the intended automatic Voice Mode playback.

# 6. INTERRUPTING EMMAUS

This is required.

While Emmaus is speaking, the user must be able to tap the microphone and begin speaking again.

When this happens:

1. stop Emmaus audio immediately
2. stop/cancel pending TTS where possible
3. begin recording
4. transcribe
5. send the new request through Ask Emmaus
6. speak the new answer

Do NOT allow the old response to continue speaking over the user.

---

# 7. DO NOT CREATE DUPLICATE AUDIO

Ensure only ONE speech playback instance exists at a time.

Starting another response must cancel/stop the previous audio.

Navigating away from Voice Mode must stop playback.

Closing Ask Emmaus must stop playback.

Unmounting the component must clean up:

* Audio objects
* object URLs
* streams
* MediaRecorder
* timers
* event listeners
