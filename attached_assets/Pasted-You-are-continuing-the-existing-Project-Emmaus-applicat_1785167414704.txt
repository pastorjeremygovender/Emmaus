=====================================================
SPRINT NAME

Emmaus Development Mode

=====================================================
OBJECTIVE

Administrators need to test all Daily Rhythm content without waiting one calendar day between entries.

Create a safe Development Mode that bypasses Daily Rhythm release restrictions only for authorised development and administrator accounts.

Normal members must continue experiencing one new Daily Rhythm day per calendar day.

=====================================================
AUTHORISED ACCESS

Development Mode may be available only to:

- Super Administrators
- Explicit development/test accounts
- Users with an existing development-mode permission or flag

Do not enable it for ordinary members.

Do not identify development users by display name or email text where a proper role or flag can be used.

Enforce access on both the interface and server/data layer.

=====================================================
DEVELOPMENT MODE CONTROL

Add an admin-only Development Mode control.

Place it somewhere appropriate for development tools, such as:

Admin Portal → Settings → Development

or an existing developer toolbar.

Control:

Development Mode

Off / On

Supporting text:

Temporarily bypass member scheduling restrictions while testing Emmaus.

Show a visible but understated development indicator when enabled:

Development Mode

This indicator must never appear to normal members.

=====================================================
DAILY RHYTHM BEHAVIOUR WHEN ENABLED

When Development Mode is ON for an authorised account:

- All Published Daily Rhythm days are immediately accessible.
- Future-day calendar locks are bypassed.
- “You’re ahead of the rhythm” is not shown.
- The tester may open any Published day directly.
- The tester may move forward or backward between days.
- Previous Days may include all Published entries.
- Direct links to Published future days are permitted for the authorised tester.
- Draft entries remain hidden on the normal member side unless using Content Studio preview.
- Deleted or unpublished entries remain inaccessible.

Do not automatically mark days complete merely because they were opened.

=====================================================
PRODUCTION BEHAVIOUR WHEN DISABLED

When Development Mode is OFF, or the user is not authorised:

- One new Daily Rhythm day unlocks per local calendar day.
- Future days remain locked.
- Review Today never advances progress.
- Replay mode never changes progress.
- Existing completion and scheduling rules remain unchanged.

No production behaviour may be weakened by this feature.

=====================================================
TEST DAY NAVIGATION

When Development Mode is enabled, add an admin-only testing control to the Daily Rhythm reader or developer toolbar:

Preview Day

Allow selection from all Published Daily Rhythm days.

Display:

- Day number
- Title
- Publication status

Opening a selected day must use the real member-facing shared renderer.

Do not create a separate fake preview design.

=====================================================
PROGRESS SAFETY

Development Mode bypasses scheduling only.

It must not silently change:

- Completion history
- Current production day
- Completion dates
- Streak data
- Member analytics
- Journey unlock state

Provide a separate explicit testing action if progress changes are needed.

Do not combine “open day” with “complete day.”

Reset your Daily Rhythm test progress?

This affects only your development account.

Buttons:
