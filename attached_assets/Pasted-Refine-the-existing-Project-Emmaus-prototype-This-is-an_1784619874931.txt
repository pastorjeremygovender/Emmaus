Refine the existing Project Emmaus prototype.

This is an EDIT of the current working application. Do not rebuild the project, replace the architecture, change the technology stack, remove working functionality, or add new features.

Preserve all current routes, authentication behaviour, demo mode, Firestore-ready structure, journey data, progress tracking, admin interface, bottom navigation and existing working interactions.

The purpose of this edit is to improve the emotional experience, readability and mobile presentation of the existing prototype.

Work carefully and make a checkpoint before editing.

## Core rule

Project Emmaus should feel like opening a calm, personal devotional rather than viewing a software dashboard.

The app must remain:

- clean
- warm
- calm
- spacious
- Christ-centred
- easy for non-technical users
- mobile-first
- encouraging rather than guilt-driven

Do not introduce visual clutter, large dashboards, excessive animations, gradients, stock photography, competitive elements or new product features.

## 1. Preserve the current design direction

Keep:

- the existing soft white or warm-neutral background
- the current restrained blue/teal accent direction
- the serif heading style
- the simple rounded cards
- the four bottom navigation tabs
- the current journey and sermon content
- all working routes and interactions

Refine the current design rather than replacing it.

## 2. Improve mobile layout

The current preview is often shown in a wide browser window, but the primary design target is a mobile phone.

Create a centred mobile content container with:

- maximum width around 480px on desktop
- full width on mobile
- comfortable left and right page padding
- content that never stretches excessively across desktop screens
- bottom padding sufficient to keep content above the fixed navigation bar
- no horizontal scrolling

Ensure all screens look intentional at approximately:

- 360px width
- 390px width
- 430px width
- desktop preview width

Do not make the mobile app look like a narrow desktop website.

## 3. Typography and readability

Increase readability throughout the app.

Use approximately:

- page titles: 30–36px
- major card titles: 23–28px
- body text: 17–19px
- labels and metadata: 13–15px
- buttons: 16–18px

Use a comfortable body line height of approximately 1.55–1.7.

Do not make every heading oversized.

Keep serif typography for meaningful titles and use the existing clean sans-serif style for body text and controls.

Improve contrast for pale grey labels and text. Some current labels are too faint.

- “Good morning, Jeremy.”
- “Good afternoon, Jeremy.”
- “Good evening, Jeremy.”

Use the actual preferred name dynamically.

Under the greeting, display one short line:

“Let’s take the next step together.”

Then display the primary journey.

Refine the primary journey card to show:

DAY 1 OF 7

Jesus Meets You Here

A short one- or two-sentence invitation based on the existing journey description.

Continue

Preserve dynamic day and progress data. Do not hard-code Day 1 if progress already supports other days.

Do not add a large progress bar.

If a streak is shown, keep it subtle and encouraging.
