==================================================

1. REQUEST STATE RESET

After every completed, failed, aborted or timed-out request:

- isSubmitting must reset

- pending request state must clear
- the stream reader must be released
- the response body must be closed appropriately
- the current AbortController must be cleared

Use finally blocks or equivalent reliable cleanup.

2. NEW ABORT CONTROLLER PER TURN

Create a fresh AbortController for every submitted message.

Do not reuse an aborted or completed controller.

Do not allow the previous request timeout to abort a later request.

Clear each request’s timeout after that request completes.

3. SEQUENTIAL TURNS

Allow a new message after the previous response has fully completed.

While a response is actively streaming:

- prevent duplicate submissions
- do not silently discard messages
- keep the send control visibly disabled if submission is unavailable

After completion:

- re-enable the composer immediately
- allow the next valid message to submit

5. ERROR VISIBILITY

If a follow-up request fails, show the existing calm user-facing error:

“Ask Emmaus could not respond just now. Please try again.”

- emits its final completion event
