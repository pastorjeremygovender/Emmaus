- five authored steps appeared as if only one existed;
- Continue disappeared or resolved incorrectly;
- View Previous Steps reported that no previous steps existed;
- progress totals were wrong;
- the app surfaced the wrong or incomplete Journey data.

Fix both:

1. Existing affected Journey data.
2. All future step creation and import behaviour.

3. PERMANENTLY FIX STEP CREATION
====================================================

- manual Add Step;
- Journey import;
- Journey generation;
- duplication or cloning, if supported.

When creating a new step, inherit the parent Journey’s status.

Required rule:

If parent.status is Published:
    new step status = Published

Otherwise:
    new step status = Draft

Use the project’s actual status enum and naming convention.

Conceptually:

const parent = await getJourney(journeyId);

const stepStatus =
  parent?.status === "Published"
    ? "Published"
    : "Draft";

createStep({
  ...
  status: stepStatus
});

Do not add a client-side visual workaround.

The correct status must be stored by the server/data layer when the step is created.

Do not maintain separate creation rules for manual creation and import. All paths must use the same canonical creation function or shared status resolver.
