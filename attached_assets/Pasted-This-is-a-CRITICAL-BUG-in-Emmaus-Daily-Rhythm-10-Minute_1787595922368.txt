CORE RULE 1 — ONLY ONE NEW 10 MINUTES WITH JESUS STEP PER DAY

A user must NEVER be able to unlock more than one new 10 Minutes with Jesus Step on the same calendar day.

Navigation must NEVER advance Daily Rhythm progress.

Completing a Step must NEVER immediately increment the current Step.

"Back to Today's Steps", browser back, page refresh, reopening the card, logging out/in, changing devices, reopening the PWA, or any other navigation action must not change the user's current Daily Rhythm Step.

Required behaviour

1. A brand-new user starts on Day 1.

2. When Day 1 is first made available, persist the date on which it was unlocked.

3. Completing Day 1 only records Day 1 as completed.

4. Completing Day 1 does NOT set the user's current day to Day 2.

5. For the remainder of that calendar day, Day 1 remains the user's current Daily Rhythm Step, even though it is completed.

6. Day 2 can only become available on a LATER calendar date AND only if Day 1 was completed.

7. If Day 1 was not completed, it remains the current Step the following day. Users must proceed sequentially.

8. Previous Days are review-only. Opening, closing, completing, or navigating through Previous Days must NEVER alter the current Daily Rhythm position.

9. The server/database must be the authority for progression.

Do not rely on:

- React state
- localStorage
- sessionStorage
- route state
- query parameters
- card index
- array position
- browser/device date
- client-side "currentDay + 1" logic

to determine which new Daily Rhythm Step is available.

10. Store timestamps in the database and determine the user's calendar date consistently.

Emmaus currently operates in South Africa, so use Africa/Johannesburg unless the user has an explicitly stored timezone.

Do not allow manipulation of the browser/device clock to bypass the daily restriction.

11. Progression must be completely user-specific.

One user's completion, unlock, or Daily Rhythm position must NEVER affect another user.

CORE RULE 2 — DAILY RHYTHM IS THE DEFAULT FIRST OPENING OF EMMAUS EACH DAY

This is an important existing Emmaus product rule and must be reinforced.

The FIRST time a user opens Emmaus on a new calendar day, Emmaus should default directly to that user's current 10 Minutes with Jesus Daily Rhythm experience.

The intended flow is:

FIRST OPEN OF EMMAUS TODAY
→ Open directly into today's/current 10 Minutes with Jesus Daily Rhythm Step.

AFTER THAT FIRST DAILY OPEN
→ Normal Emmaus opening behaviour returns.
→ Open to Today's Steps.

Therefore:

- Daily Rhythm is the default first opening screen of Emmaus each new day.
- This should happen ONCE per calendar day per user.
- Subsequent opens of Emmaus on the same calendar day should open to Today's Steps.
- Do not repeatedly force the user back into Daily Rhythm every time they open Emmaus that day.

Persist this state reliably per user.

Do NOT implement this solely using localStorage.

The system needs to know whether that authenticated user has already had their first Emmaus opening for that calendar date.

This must also work across devices.

Example:

User opens Emmaus on phone at 7:00 AM.

→ Daily Rhythm opens automatically.

User closes Emmaus.

User opens Emmaus again at 10:00 AM.

→ Today's Steps opens.

User opens Emmaus on laptop at 2:00 PM.

→ Today's Steps opens because the user's first daily opening has already occurred.

The next calendar day:

User opens Emmaus.

→ Daily Rhythm opens automatically again.

After that:

→ Today's Steps.

Do NOT confuse "first daily opening" with "unlock next Step."

→ Day 1 Daily Rhythm opens.

→ Today's Steps opens.

→ Day 2 becomes available.

→ Emmaus opens directly into Day 2.

→ Day 2 remains the current completed Step for the rest of Tuesday.

Wednesday:

→ Same process for Day 3.
