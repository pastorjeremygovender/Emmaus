PROJECT EMMAUS — COMPLETE BIBLE MVP WITH MULTIPLE TRANSLATIONS

Implement directly in the existing Project Emmaus codebase.

This is a major completion build, not a conceptual redesign.

Do not modify Ask Emmaus, Rooms, Media Studio, Sermon Companion, authentication, Admin Portal or unrelated Journey functionality.

Do not fabricate or paraphrase Bible verses.

Do not mark this task complete based only on TypeScript checks or the existence of files. Test the complete reading experience in the running application.

==================================================
1. LEGAL TRANSLATION SOURCES
==================================================

Use only verified public-domain or explicitly authorised development Bible data.

For this MVP, provide at least two complete English translations from legally usable sources, preferably:

- World English Bible (WEB)
- American Standard Version (ASV)

KJV may also be included only when sourced and labelled appropriately for the territories and development use involved.

Before importing any text:

- verify the source licence or public-domain declaration
- record source attribution and licence information in project documentation
- do not scrape copyrighted Bible websites
- do not copy text from BibleGateway, YouVersion or other services without explicit API or content permission
- do not represent public-domain development translations as NIV, GNT or ESV

Display translation names and abbreviations accurately.

Add unavailable future translations to architecture/configuration only, not as selectable empty or misleading options.

NIV remains the intended preferred future translation after proper licensing.

==================================================
2. PROVIDER ARCHITECTURE
==================================================

Preserve and complete the existing Bible Provider abstraction.

The Bible UI must not be coupled directly to one translation dataset.

The provider contract should support:

- list translations
- retrieve book metadata
- retrieve chapter text
- retrieve verse range
- search
- attribution and licence metadata
- optional audio availability
- optional offline availability

Each translation should have stable identifiers.

The active translation must be resolved through the provider/service layer.

Do not scatter translation-specific conditions throughout React components.

4. COMPLETE BIBLE DATA
==================================================

Import or connect the full text for every chapter of every book for each included public-domain translation.

Requirements:

- text must be stored or retrieved through the Bible Provider layer
- verse numbers must be preserved
- chapter boundaries must be accurate
- book names must map consistently across translations
- text must not be held in one enormous frontend bundle
- do not make the browser download the entire Bible at startup
- load chapter data on demand
- support reasonable caching
- avoid repeatedly downloading the same chapter during one session

If data is imported into the database:

- use an idempotent import or seed process
- do not create duplicates when the import runs again
- include translation, book, chapter and verse indexes
- report how many translations, books, chapters and verses were imported

If a trusted public-domain Bible API is used:

- isolate it behind the provider abstraction
- handle network failure gracefully
- do not expose private API credentials
- document rate and availability limitations
- retain the ability to migrate to locally hosted or licensed data later
