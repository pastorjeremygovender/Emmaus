# Replit Repair Prompt — Manual Walk Authoring / Walk Complete Bug

We have discovered a structural bug in Emmaus Content Studio while manually authoring a Walk.

This is **not a request to create or rewrite any content**.

The content already entered must be preserved exactly.

## Context

A Walk called:

**Who Is God?**

was manually created inside the Journey:

**Come and See**

The Walk was configured with:

**5 Steps**

The administrator then manually entered:

* Walk Introduction
* Day 1
* Day 2
* Day 3
* Day 4
* Day 5

All of this content must remain untouched.

## Current bug

When the Walk was created with 5 Steps, the editor initially showed:

* Walk Introduction
* Day 1
* Walk Complete

Instead of generating the five configured Day/Step slots immediately.

The administrator then advanced through the Walk by clicking what appeared to be **Walk Complete**.

Each time this happened, Emmaus dynamically created the next Day.

This caused the following behaviour:

* After Day 1, Walk Complete effectively became Day 2
* After Day 2, it became Day 3
* This continued through Day 5
* After completing Day 5 and clicking Walk Complete, Emmaus incorrectly created:

**Day 6 — Walk Complete**

The left navigation now shows:

* Walk Introduction
* Day 1
* Day 2
* Day 3
* Day 4
* Day 5
* Day 6
* Walk Complete

This is incorrect because the Walk was configured with only 5 Steps.

## Required fix

Fix the manual Walk authoring engine so that the configured number of Steps is respected.

For a Walk created with 5 Steps, the editor should generate and preserve this structure from the beginning:

* Walk Introduction
* Day 1
* Day 2
* Day 3
* Day 4
* Day 5
* Walk Complete

The administrator must not have to click Walk Complete in order to manufacture the next Day.

## Walk Complete behaviour

Walk Complete must be a distinct final stage.

It must never:

* create another Day
* increment the Step count
* behave as a hidden next-step generator
* inherit or prepopulate the title "Walk Complete" into a normal Day
* permit Day 6 in a Walk configured for 5 Steps

After the administrator saves Day 5, the next destination should be the genuine Walk Complete editor.

## Preserve existing content

Do not delete, overwrite, migrate, regenerate, reorder, rewrite or otherwise alter the content already entered into:

* Walk Introduction
* Day 1
* Day 2
* Day 3
* Day 4
* Day 5

The administrator spent time entering this manually.

Preserve all existing values exactly as stored.

## Repair the current Who Is God? Walk

For the existing Walk:

**Who Is God?**

remove only the erroneously created empty **Day 6** record if it contains no genuine authored content.

Do not remove Day 6 blindly if it contains content. First confirm that it is the erroneous empty record created by this bug.

The corrected Walk should contain:

* Walk Introduction
* Day 1
* Day 2
* Day 3
* Day 4
* Day 5
* Walk Complete

## Walk Complete editor

Walk Complete should have its own completion-message authoring experience.

Do not treat it as a standard numbered Day.

It should allow the administrator to create a short final completion experience, such as:

* Completion heading/title
* Completion message
* Optional Scripture/reference if already supported by the architecture
* Optional encouragement/reflection if already supported
* Optional next-Walk or next-Journey invitation if supported

Do not redesign this broadly. Use the existing Emmaus patterns wherever possible.

If a dedicated Walk Complete schema already exists, restore/fix its routing and rendering rather than creating a duplicate system.

## New Walk behaviour

For all future manually created Walks:

If the administrator enters:

**Number of Steps: 5**

Emmaus must immediately create or expose exactly:

* Day 1
* Day 2
* Day 3
* Day 4
* Day 5

plus:

* Walk Introduction
* Walk Complete

If the administrator enters 7 Steps, expose exactly Day 1 through Day 7.

The number entered during Walk creation must be the source of truth unless the administrator deliberately changes the Step count later through a supported editing flow.
