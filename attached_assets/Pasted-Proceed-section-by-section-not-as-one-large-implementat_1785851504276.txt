==================================================
PEOPLE ARCHITECTURE
==================================================

The existing Emmaus user/profile record remains canonical whenever one exists.

Attendance-only people may be stored in pastoral_persons or the equivalent audited structure.

Rules:

- pastoral_persons supplements existing users.
- It must not become a second independent member database.
- Include linked_user_id for later account linking.
- Once linked, the person must appear as one person.
- Do not duplicate attendance, notes or history after linking.
- Prevent two attendance-only records from being linked to the same Emmaus account.
- Search existing users and attendance-only people together through one service layer.

- Sunday Evening
- Prayer Meeting
- Bible Study
- Youth
- Men’s Meeting
- Ladies’ Meeting
- Made Free
- Volunteer Training
- Special Event

Do not hard-code these permanently.

==================================================
MEETING SESSIONS
==================================================

Allow an authorised leader to create a dated session from a meeting type.

Fields:

- Meeting type
- Date
- Start time, optional
- Location, optional
- Notes, optional
- Status: Scheduled, Completed, Cancelled
- Attendance totals

Cancelled sessions must never count as missed attendance.

==================================================
ATTENDANCE REGISTER
==================================================

Build a fast, reliable manual attendance register.

The register must support:

- Search all existing Emmaus users.
- Search attendance-only people.
- Alphabetical list.
- Recent attenders.
- Add visitor.
- Link to an existing person if a match is found.
- Select multiple people.
- Mark selected Present.
- Mark selected Visitor.
- Mark selected Apology.
- Mark selected Absent.
- Mark selected Not Expected.
- Correct an attendance record.
- Save continuously or with a clear Save action.
- Show a reliable “Attendance saved” confirmation.
- Prevent duplicate attendance records for the same person and session.
- Display totals by status.

Do not default every person to Absent.

A person with no attendance record must remain unrecorded until intentionally marked or the register is finalised.

==================================================
ATTENDANCE EXPECTATIONS
==================================================

Add a simple way to indicate which meetings a person normally attends.

Examples:

- Usually attends Sunday Morning.
- Not expected at Sunday Evening.
- Youth participant.
- Made Free participant, restricted.

This data will later power care rules.

For now, only record and display expectations.

Do not generate alerts yet.

==================================================
ATTENDANCE STATUSES
