Ticket #004 — Restore Ask Emmaus as the flagship discipleship guide

We are working on branch:

launch-13-august

Objective:

Restore and strengthen the existing Ask Emmaus behaviour that previously referenced ICC sermons with wording such as:

“Pastor Jeremy preached about this…”

Ask Emmaus must not behave like a generic Christian chatbot. It must guide a person using Scripture, ICC teaching and existing Emmaus content.

IMPORTANT:

- First inspect the existing Ask Emmaus implementation, sermon retrieval/indexing, ICC memory/context, recommendation logic and relevant database tables.
- Recover and reuse existing working architecture wherever possible.
- Do not build a second competing Ask Emmaus system.
- Do not redesign the Ask Emmaus interface.
- Do not modify unrelated navigation or content flows.
- Fix only what is necessary for the pilot-quality Ask Emmaus experience described below.

PILOT RESPONSE REQUIREMENTS

For a suitable pastoral question such as:

“I have been struggling with anger.”

Ask Emmaus should produce a response with this hierarchy:

1. A warm, empathetic opening.
2. Relevant Scripture as the primary foundation.
3. Relevant ICC teaching where available:
   - Use wording such as:
     “Pastor Jeremy preached about this in…”
   - Include sermon title.
   - Include a real timestamped YouTube link when timestamp data exists.
   - Never invent a sermon, quotation, timestamp or URL.
4. Recommend relevant existing Emmaus content where available:
   - one Walk or Journey;
   - one Bible Study or Bible passage with study content;
   - one Daily Devotional or Psalm entry;
   - one Sermon Companion if relevant.
5. Include a short prayer.
6. End with one clear “Your next step” section.
7. If the user belongs to a Room, gently suggest sharing a prayer request with the Room. Do not require it.

CONTENT RULES

- Scripture is primary.
- ICC sermons and approved ICC content are secondary.
- General AI knowledge may connect the response but must not replace Scripture or fabricate ICC teaching.
- Use only published member-visible Emmaus content for recommendations.
- Never expose drafts, admin-only content or unpublished resources.
- Never claim Pastor Jeremy preached on something unless a matching indexed sermon record exists.
- Never fabricate timestamps.
- If no relevant ICC sermon is found, omit the sermon section naturally rather than apologising or inventing one.
- Recommendations must link to the correct existing member route.
- Limit recommendations to the most relevant item of each type. Do not overwhelm the user.
- Preserve the Emmaus voice: Christ-centred, gentle, pastoral and practical.

INVESTIGATION REQUIREMENTS

Before editing, identify and report internally:

1. Where the previous “Pastor Jeremy preached…” behaviour was implemented.
2. Whether sermon data still exists in the database, JSON files, YouTube archive or retrieval index.
3. Why that behaviour stopped appearing.
4. Whether Ask Emmaus currently receives:
   - sermon context;
   - ICC memory;
   - Walks/Journeys;
   - Bible Studies;
   - Daily Devotionals;
   - Sermon Companions;
   - Room membership.
5. Which existing APIs and components can be reused.

IMPLEMENTATION REQUIREMENTS

- Restore sermon retrieval in the main Ask Emmaus response pipeline.
- Load the approved ICC/Emmaus memory before generating the answer.
- Retrieve relevant published resources from existing data sources.
- Return structured recommendation data rather than relying only on prose.
- Render recommendations as existing Emmaus content cards or safe internal links where components already exist.
- Preserve conversation history.
- Preserve the recently added next-step and pastoral handoff behaviour.
- Do not hard-code sample sermon titles or content.
- Do not seed fake data merely to make tests pass.
