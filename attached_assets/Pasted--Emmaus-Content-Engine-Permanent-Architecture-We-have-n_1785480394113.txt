# Emmaus Content Engine (Permanent Architecture)

We have now reached the point where Emmaus needs a permanent, repeatable content engine.

Do NOT redesign the UI or change any existing user experience that is already working.

Instead, refactor the backend and Content Studio so every future piece of discipleship content uses the exact same framework.

The objective is that after this refactor, creating new content requires ONLY entering content—not building new screens, routing or navigation.

---

OBJECTIVE

Build one universal content engine that powers:

• Daily Rhythm
• Daily Devotionals
• Walks
• Journeys (Collections)
• Sermon Companions
• Bible Studies
• Made Free
• Future Courses
• Seasonal Studies
• Any future discipleship content

Every one of these must inherit the same architecture.

Never create another separate content system.

CONSIDER THIS

Written only in Emmaus Voice.

Must:

• point people to Jesus

• be encouraging

• be conversational

• be Scripture-centred

Never:

• guilt people

• lecture people

• use legalistic language

• become academic

• include long numbered lists

IMPORTANT

Do NOT redesign any existing Emmaus screens.

Do NOT change navigation that is already working.

Do NOT modify the Emmaus design language.

This is an architectural refactor that creates a reusable content engine underneath the existing UI.

The goal is that once complete, every future Walk, Journey, Bible Study, Devotional or Course automatically inherits the Emmaus framework.

From this point forward we should only be creating content, not rebuilding infrastructure.

This architecture becomes the permanent foundation of Emmaus.
