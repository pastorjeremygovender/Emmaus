Project Emmaus — Standardize Self-Paced Content Buttons to “Continue”

We are finalising the member-facing navigation language for sequential content.

The current app uses several different green-button labels across self-paced content, including:

- Open Devotional
- Open Companion
- Open Journey
- Begin Sermon Companion
- Review
- Resume
- Continue

This is unnecessarily inconsistent.

From now on, every green primary action for self-paced sequential content should use one simple label:

Continue

Daily Rhythm is the only exception.

Do not change Daily Rhythm wording in this task.
Do not change progress logic.
Do not change routes.
Do not change card design.
Do not remove View Previous Days / Previous Entries navigation.

====================================================
LOCKED BUTTON RULE
====================================================

For all self-paced content, the green primary button reads:

Continue

Apply this to:

- Daily Devotionals
- Sermon Companions
- Journeys
- Bible Studies
- Standalone Journeys
- Collection-based Journeys
- future self-paced sequential content

Use Continue regardless of whether the member is:

- opening the content for the first time;
- returning to an unfinished entry;
- moving to the next available entry;
- returning after completing a previous entry.

The app should resolve the correct destination from progress.

The button label does not need to explain the internal state.

====================================================
DAILY RHYTHM EXCEPTION
====================================================

Daily Rhythm remains system-led and calendar-paced.

Do not replace its button with Continue.

Daily Rhythm should use state-aware wording such as:

- Open Today’s Time
- Return to Today’s Time
- Review
- Review Latest Reading

according to the established Daily Rhythm rules.

Daily Rhythm automatically resolves the correct real published day.

====================================================
CARD BEHAVIOUR
====================================================

For self-paced content, clicking Continue must:

1. load the member’s progress;
2. determine the correct real published entry;
3. open the first uncompleted eligible entry;
4. if all entries are complete, open the latest completed entry in review mode;
5. never open a draft or nonexistent entry;
6. never refresh the same page without navigation.

Examples:

Psalms Daily Devotional
Continue
→ opens the next uncompleted published devotional entry.

Jesus at the Center
Continue
→ opens the next uncompleted published Sermon Companion reflection.

Coming to Jesus
Continue
→ opens the next uncompleted published Journey step.

If no progress exists:

Continue
→ opens Entry or Day 1.

====================================================
COMPLETED CONTENT
====================================================

Even when the full self-paced content is completed, keep the green button label:

Continue

In this state, Continue may open:

- the content overview;
- the latest completed entry;
- the first entry in review mode;

according to the existing content-detail flow.

Do not use a separate green Review button on the card.

Review navigation is already available through:

- View Previous Entries;
- View Previous Reflections;
- View Previous Steps;
- the content detail screen.

The card should stay simple.

====================================================
SECONDARY REVIEW LINKS
====================================================

Preserve the secondary link beneath the green button.

Use content-specific wording:

Daily Devotional:
View Previous Entries →

Sermon Companion:
View Previous Reflections →

Journey:
View Previous Steps →

Bible Study:
View Previous Studies →

Daily Rhythm:
View Previous Days →

These links must open the shared historical/review experience.

They must not change progress.

They must use source-aware navigation and return to the exact page and tab from which they were opened.

====================================================

- first uncompleted published entry;

Do not route by title.

Use real IDs and published-entry order.
