IMPLEMENT THE LOW-COST EMMAUS VOICE ARCHITECTURE

Emmaus must remain free for users and have the lowest sustainable operating cost.

Replace the current ElevenLabs-dependent Voice configuration with a low-cost, provider-neutral system.

Target architecture:

VOICE INPUT

- OpenAI gpt-4o-mini-transcribe for dependable tap-to-speak transcription

EMMAUS INTELLIGENCE

- the existing canonical Ask Emmaus pipeline
- Scripture first
- Local Church resources
- authenticated user context
- validated Emmaus actions

VOICE OUTPUT

- device/browser speech synthesis as the free default
- optional OpenAI TTS for comparison and higher-quality speech
- ElevenLabs retained but disabled behind a feature flag

PUBLISHED RESOURCE READING

- provider-neutral Read to Me player
- generate once and cache reusable audio where appropriate
- never regenerate identical published content for every user

FUTURE

- native on-device speech recognition and TTS
- dramatized Bible audio
- interchangeable audio providers

Create a checkpoint before changing anything.

Do not republish automatically.

Do not delete the existing ElevenLabs integration. Isolate it safely so it can be restored for comparison if needed.

==================================================
3. REPLACE ELEVENLABS TRANSCRIPTION
==================================================

Use OpenAI `gpt-4o-mini-transcribe` for normal tap-to-speak transcription.

Required flow:

1. User taps microphone.
2. Browser requests microphone permission where necessary.
3. Start MediaRecorder.
4. Record one bounded utterance.
5. Stop automatically after reliable end-of-speech or when user taps Stop.
6. Validate recorded duration and byte size.
7. Send audio securely to the Emmaus server.
8. Emmaus server calls OpenAI transcription.
9. Return transcript and metadata.
10. Route transcript through the canonical Ask Emmaus intent system.
11. Release microphone and recorder resources.

Do not expose the OpenAI API key to the client.

Supported recorded formats must match both:

- actual browser MediaRecorder output
- OpenAI transcription input requirements

Detect the real MIME type rather than hard-coding one.

Support common mobile formats such as:

- audio/webm
- audio/mp4
- audio/m4a where produced
- audio/wav where available

If format conversion is necessary, perform it safely on the server and clean up temporary files.

Do not create persistent raw-audio storage unless explicitly required.

==================================================
4. CLEAN RECORDING LIFECYCLE
==================================================

The recent Voice system worked for two questions and then displayed “Transcription is not available.”

Ensure every transcription attempt—successful or failed—performs cleanup:

- stop every MediaStream track
- stop and release MediaRecorder
- clear audio chunks
- clear timers
- remove event listeners
- close previous provider request/session
- revoke temporary object URLs
- reset abort controllers
- reset Voice state
- allow the next tap to create a completely new recording session

Only one active transcription request is allowed per user interface instance.

Prevent double taps from creating overlapping requests.

Add a request/session ID so late results from an old recording cannot overwrite a new session.

==================================================
5. TRANSCRIPTION RETRY AND ERRORS
==================================================

Retry once for:

- temporary network error
- timeout
- OpenAI 429 when Retry-After permits
- temporary OpenAI 5xx failure

Do not automatically retry:

- empty recording
- microphone permission denial
- invalid audio
- missing authentication
- exhausted account usage limit

Use clear user-facing messages:

NO SPEECH

“I couldn’t hear any speech. Please try again.”

MICROPHONE DENIED

“Emmaus needs microphone permission for Voice. You can still type your question.”

TEMPORARY FAILURE

“Voice is temporarily unavailable. Please try again.”

NETWORK FAILURE

“Your connection was interrupted. Please try again.”

Do not expose provider names, API errors or billing information to normal users.

Keep typed Ask Emmaus fully functional whenever Voice fails.

==================================================
6. DEVICE SPEECH AS FREE DEFAULT OUTPUT
==================================================

Use browser/device `speechSynthesis` as the default spoken-output trial.

This applies to:

- Ask Emmaus spoken answers
- short navigation confirmations
- player confirmations
- short resource sections
- testing Read to Me

Requirements:

- enumerate available device voices
- select the best appropriate English voice deterministically
- prefer `en-ZA` where a good voice exists
- otherwise prefer a high-quality `en-GB` voice
- otherwise use the best available English voice
- retain the selected voice for the session
- do not change voice between paragraphs
- use a calm, mature male voice where the device provides one
- use natural rate, pitch and volume defaults
- allow admin/test configuration of rate and voice
- do not expose personality or accent customization to normal users

Emmaus has one centrally defined identity. Users may turn Voice on or off and use accessibility controls, but must not redefine Emmaus’s personality.

Do not speak:

- URLs
- Markdown markers
- raw database labels
- technical metadata
- card-button labels
- sermon IDs

==================================================
7. DEVICE TTS PLAYER LIMITATIONS
==================================================

Device speech synthesis may not support dependable background playback or precise saved audio time.

Represent progress using logical content segments:

- verse
- paragraph
- section
- Step
- devotional segment

Save progress after each completed segment.

If device speech pauses or stops when the PWA is backgrounded:

- preserve the last completed segment
- display Paused
- allow Resume
- do not claim screen-off support

Do not force browser speech synthesis into unsupported background behaviour.

9. CACHE REUSABLE GENERATED AUDIO
==================================================

Do not generate paid TTS repeatedly for identical published content.

Reusable content includes:

- Daily Rhythm sections
- Daily Devotionals
- Walk introductions
- Walk Steps
- Journey introductions
- Bible Study content
- Sermon Companion content
- other fixed published Emmaus resources

Use a safe cache key based on:

- tenant
- canonical resource type
- canonical resource ID
- content version/hash
- section or segment ID
- TTS provider
- voice
- model
- speaking settings
- language

On a cache hit:

- reuse the existing authorised audio asset

On content edit or republish:

- create a new versioned cache key
- stop serving stale audio

Do not cache personalized Ask Emmaus answers globally.

Do not allow one tenant’s private audio to become accessible to another tenant.

Do not pre-generate the entire Emmaus library during this task.

Generate and cache on first use or through a deliberate admin action.
