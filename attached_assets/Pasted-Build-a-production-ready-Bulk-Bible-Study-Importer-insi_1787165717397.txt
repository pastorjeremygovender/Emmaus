Build a production-ready Bulk Bible Study Importer inside the existing Emmaus Admin → Bible Study system.

IMPORTANT

Do not redesign or replace the existing Bible Study user experience.

Do not remove or rename existing Bible Study fields.

Do not break any currently published Bible Study content.

Inspect the existing database schema, APIs, routes, admin components and Bible Study rendering before making changes.

Reuse the existing architecture wherever possible.

Create a restore/checkpoint before beginning any database migration or major structural change.

The goal is to allow an admin to generate structured Bible Study content externally, paste the entire structured block into Emmaus once, preview it, and have Emmaus automatically populate all the correct existing Bible Study fields.

The importer must support:

* one chapter
* multiple chapters
* an entire Bible book
* multiple passage groups within each chapter

The admin should not have to manually paste content into individual fields.

# PARSING RULES

BOOK:

Sets the current Bible book.

Required before chapters are imported.

CHAPTER:

Starts a new chapter.

Everything following belongs to that chapter until the next CHAPTER or BOOK marker.

TITLE:

Optional chapter Study title.

CHAPTER_OVERVIEW:

Chapter-level field.

Only one Chapter Overview per chapter.

PASSAGE:

Starts a new passage Study record.

All Study fields following PASSAGE belong to that passage until another PASSAGE, CHAPTER or BOOK marker appears.

Map fields as follows:

EXPLANATION → Explanation

PASSAGE_CONTEXT → Passage Context

KEY_TRUTH → Key Truth

REFLECTION → Reflection

PRACTICAL_APPLICATION → Practical Application

RELATED_SCRIPTURES → Related Scriptures

HISTORICAL_BACKGROUND → Historical Background

ORIGINAL_LANGUAGE → Original Language

POINTS_TO_JESUS → How This Points to Jesus

Field names should be case-insensitive when parsing.

Whitespace around labels should be ignored.

Blank lines must not affect parsing.

Do not require a separator such as "---".

If separators are included, ignore them safely.

# OPTIONAL FIELDS

If a field has no content, treat it as absent.

On the user Study screen, only show optional sections when content exists.

Chapter Overview remains available at chapter level where one has been imported.

# PASSAGE GROUPS

The importer must support passage ranges.

Examples:

Genesis 1:1-2

Genesis 1:3-5

Genesis 1:26-28

Genesis 11:1-9

Do not require every individual verse to have its own Study record.

A passage range is one Study record.

If a user taps any verse inside that range, the existing Study experience should surface the Study record associated with that range.

Example:

Study record:
Genesis 1:26-28

User taps:
Genesis 1:27

Emmaus should show the Genesis 1:26-28 Study content.

Preserve any existing individual passage behaviour that is already functioning, but add proper range matching where needed.

# VALIDATION

Before import, validate:

Bible book exists.

Chapter number is valid for that Bible book.

Passage belongs to the correct book.

Passage belongs to the correct chapter.

Verse numbers are valid where the existing Bible data allows validation.

Passage start verse is not greater than end verse.

Duplicate passage ranges inside the same pasted chapter are detected.

Unknown field labels are reported.

Required structural fields are present.

Do not reject an import merely because optional Study fields are missing.

# ERRORS AND WARNINGS

Errors must be specific.

Examples:

Genesis 3:29 is not a valid verse.

PASSAGE "Genesis 4:8-2" has an invalid range.

Chapter 51 does not exist in Genesis.

PASSAGE_CONTEXT was found before a PASSAGE marker in Genesis 6.

Unknown field "APPLICATION_NOTE" found in Genesis 8:1-5.

Differentiate:

ERROR — cannot import this item.

WARNING — can import, but admin should review.

Do not silently discard malformed content.

# DUPLICATE / EXISTING CONTENT PROTECTION

This is essential.

Before importing, detect whether a chapter or passage already has Study content.

For each affected chapter show:

Existing Study content detected.

Provide choices:

Skip Existing

Replace Study Content

Merge

Definitions:

SKIP EXISTING

Leave all currently existing Study content untouched.

Only import records that do not already exist.

REPLACE STUDY CONTENT

Replace imported Bible Study fields for the selected chapter/passages.

Do NOT delete or alter:

Preached Here

sermon links

Bible text

user notes

user highlights

saved verses

cross-reference infrastructure that was not created by this importer

any unrelated Bible metadata

MERGE

Add content only into currently empty matching Study fields.

Do not overwrite existing populated Study fields.

Default option when existing content is detected:

Skip Existing

Never overwrite published Study content silently.

# FINAL REQUIREMENT

The finished admin workflow should be:

1. Admin opens Bible Study.
2. Admin clicks Bulk Import.
3. Admin copies an AI-generated structured Bible Study batch.
4. Admin pastes the entire batch once.
5. Admin clicks Parse & Preview.
6. Emmaus identifies books, chapters, passage ranges and all Study fields.
7. Emmaus validates the content.
8. Admin chooses chapters and duplicate behaviour.
9. Admin selects Import as Draft or Import & Publish.
10. Emmaus automatically populates all correct Bible Study fields.
11. User Study pages immediately use the imported content after publication.

The objective is speed and simplicity.

An admin should be able to populate multiple complete Bible chapters without opening individual chapter records or individual Study fields.

Do not stop after building only the visual paste screen.

Complete the parser, validation, database writing, preview, duplicate protection, passage-range mapping and user-side integration so the workflow works end-to-end.
