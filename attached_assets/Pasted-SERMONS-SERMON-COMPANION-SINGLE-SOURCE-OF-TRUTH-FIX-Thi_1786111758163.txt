SERMONS + SERMON COMPANION — SINGLE SOURCE OF TRUTH FIX

This is a structural fix. Do not patch the UI by hiding individual sermon titles.

The Emmaus Content Studio must become the single source of truth for all sermons and sermon companions shown anywhere in the member app.

Before changing anything, inspect the existing sermon/companion data model and identify why the member app currently displays Sermon Companions that no longer appear in Content Studio.

Current incorrect behaviour:

Content Studio → Sermons currently shows only one sermon: New Sermon
The member app still shows:
Jesus at the Center
God Uses the Unlikely
These were deleted from Content Studio and must therefore not remain available as independent member-facing content.
The remaining sermon also appears to have an old Companion relationship/content titled God Uses the Unlikely.

Do not simply hard-code these titles out of the UI.

1. ONE AUTHORITATIVE SERMON DATA SOURCE

Audit all places from which the member app retrieves:

sermons
sermon companions
current week's sermon
previous sermon companions
Today's Steps sermon content
Next Steps → Sermon Companions

There must be one authoritative relationship:

Sermon → Sermon Companion

A Sermon Companion cannot exist as unrelated member-facing seeded/demo content.

The member app must derive available Sermon Companions from the sermons managed in:

Admin → Content Studio → Sermons

Remove any runtime fallback arrays, seed/demo companion lists, legacy hard-coded sermon companions, or alternate queries currently supplying member-facing content.

Do not delete unrelated database infrastructure until you have established what it is used for.

2. PUBLISHING RULE

A Sermon Companion should appear to members only when its parent sermon/companion has been published.

Rules:

Draft

Admin only.
Never visible in member app.

Published

Available in member app.

Unpublished

Immediately stops appearing as available member content.

Deleted

Immediately stops appearing from all member discovery lists.

If historical user-progress records reference deleted/unpublished content, preserve those records internally for audit/history purposes, but do not continue presenting the deleted content as an available Sermon Companion.

Do not allow orphan Sermon Companion records to appear in the member UI.

Add a permanent Sermon Companion card to:

This Week's Sermon

When a new sermon becomes This Week's Sermon, the permanent Today's Steps card automatically updates to that sermon.

Previous completed/in-progress companions must retain user progress and remain accessible through Sermon Companions/history where appropriate.

6. REMOVE "THE PASTOR" FROM GENERATED CONTENT

Sermon Companion generation must never refer to the speaker impersonally as:

"the pastor"

This currently creates unnatural sentences such as:

"The pastor retells..."
"The pastor said..."

Update the Sermon Companion generation instructions globally.

If the sermon has a speakerName, use the speaker naturally where appropriate.

For ICC content where the speaker is Jeremy Govender, the reader-facing wording may use:

Pastor Jeremy

Examples:

Instead of:

"The pastor retells how God reduced Gideon's army..."

use:

"Pastor Jeremy retells how God reduced Gideon's army..."

Or, where it sounds warmer and more natural:

"We spoke about how God reduced Gideon's army..."

Instead of:

"Quoting Hebrews 11:1, the pastor said..."

use:

"Reflecting on Hebrews 11:1, Pastor Jeremy explained..."

or:

"We reflected on Hebrews 11:1..."

Do not mechanically insert Pastor Jeremy into every paragraph. The Companion should remain warm, natural and devotional rather than repeatedly talking about the preacher.

Preferred hierarchy:

Speak directly about Jesus/Scripture whenever possible.
Use we reflected / we spoke about / we saw where natural.
Use the actual speaker name where attribution genuinely matters.
Never use generic the pastor.

This must be driven by the sermon speakerName field so Emmaus remains usable by other churches and speakers later.

If speakerName is unavailable, use neutral wording such as:

we reflected on

rather than inventing a pastor's identity.

Update the generator prompt/template so all future companions follow this rule.

Also correct the currently generated Companion wherever "the pastor" is already rendered, while preserving the meaning of the existing devotional content.
