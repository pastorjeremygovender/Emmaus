4. INTERRUPTION / BARGE-IN IS NOT WORKING

Manual test:
Emmaus was speaking.
User spoke over Emmaus.
Nothing happened.
Emmaus continued speaking.

This contradicts the intended Phase 2/3 behaviour.

Repair real-time interruption.

While TTS is SPEAKING:

microphone/VAD must be capable of detecting deliberate user speech.

When deliberate user speech is detected:

1. Immediately stop/pause current TTS playback.
2. Cancel remaining queued TTS sections.
3. Transition SPEAKING → LISTENING.
4. Capture the user's complete utterance.
5. Transcribe it.
6. Route it through Voice intent handling.
7. Execute the command or obtain Emmaus response.
8. Resume the continuous Voice conversation.

Examples:

Emmaus is reading Psalm 23.
User says:
"Stop."

→ reading stops.

User says:
"Explain that."

→ reading stops.
→ current verse/section is injected as context.
→ Emmaus explains it.
→ Voice conversation continues.

User says:
"Repeat that."

→ replay current/previous reading section.

User says:
"Continue."

→ resume from the correct position.

IMPORTANT:
Prevent Emmaus from hearing its own TTS.
Do not simply leave the microphone fully open and cause feedback/self-interruption.

Use the existing Phase 2 VAD/interruption architecture and diagnose why it is not firing on the real mobile device.
