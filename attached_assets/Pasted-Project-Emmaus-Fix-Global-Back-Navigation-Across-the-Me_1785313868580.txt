Project Emmaus — Fix Global Back Navigation Across the Member App

This is a global navigation regression.

Current behaviour:

The back arrow on content pages, Previous Days pages, review pages and other member screens always sends the member to Today’s Steps.

This is incorrect.

The back arrow must return the member to the exact page and tab from which the navigation was initiated.

Do not fix this only for Daily Rhythm.
Do not add separate hard-coded fixes for each content type.
Do not redesign any screens.
Do not change content, progress, publishing or completion logic.

====================================================
PERMANENT NAVIGATION PRINCIPLE
====================================================

Emmaus must use source-aware navigation.

The back arrow means:

Return to the previous meaningful Emmaus screen.

It must not mean:

Go to Today’s Steps.

Today’s Steps may only be the destination when that is genuinely the screen the member came from.

TASK 2 — CREATE ONE SHARED RETURN CONTEXT
====================================================

Create or reuse one shared navigation context, utility or route-state structure.

ReturnContext

Possible fields:

{
  sourceRoute: string,
  sourceTab?: string,
  sourceContentId?: string,
  sourceSection?: string,
  sourceScrollPosition?: number,
  fallbackRoute: string
}

Use the project’s established router and state conventions.

====================================================

Whenever a member opens content, preserve the source.

Examples:

From Today’s Steps:

{
  sourceRoute: "/walk",
  fallbackRoute: "/walk"
}

From Next Steps Daily Devotionals:

{
  sourceRoute: "/next-steps",
  sourceTab: "daily-devotionals",
  fallbackRoute: "/next-steps?tab=daily-devotionals"

From Next Steps Journeys:

{

  fallbackRoute: "/next-steps?tab=journeys"

  fallbackRoute: "/my-journey"
}

Use the actual canonical routes in the project.

====================================================
TASK 4 — BACK ARROW PRIORITY
====================================================

The shared Back action should resolve in this order:

1. Valid explicit return context passed by the source screen.
2. Valid internal router history entry.
3. Content-specific safe parent route.
4. Final fallback to Today’s Steps only when no better context exists.

Do not blindly use browser history when it could leave the Emmaus app or return to authentication, an external browser page or a stale admin screen.

Use safe internal-app history.

====================================================
TASK 5 — PRESERVE NEXT STEPS TAB
====================================================

Returning to Next Steps must preserve the selected tab.

Supported tabs:

- Daily Devotionals
- Journeys
- Sermon Companions

The member must not return to the default Daily Devotionals tab when they came from Sermon Companions or Journeys.

Persist the tab using:

- route query parameter;
- route segment;
- router state;
- session state;

according to the existing implementation.

Prefer a URL-addressable tab so refresh and browser Back remain reliable.

→ Previous Days
→ Review Day 1

TASK 9 — REFRESH SAFETY
====================================================

Ensure a safe fallback remains encoded in the URL or recoverable from session storage.

After refresh on:

- Review;
- Journey Day;
- Sermon Companion Day;
- My Bible passage;

the Back arrow must still return to the most appropriate parent screen.

Do not depend solely on ephemeral component state.

TASK 10 — EXTERNAL ENTRY SAFETY
====================================================

If a member opens a deep link directly from:

- a notification;
- a shared link;
- an external browser;
- an app shortcut;

Journey:

Sermon Companion:

Do not delay the core fix for complex scroll restoration.
