Build a mobile-first working prototype called **Project Emmaus**.

Project Emmaus is a Christian discipleship app for Isipingo Community Church. Its purpose is to help people take a meaningful next step with Jesus through short guided journeys, Scripture reflection, prayer, action steps, sermon-based devotionals, and pastoral support.

This is a prototype, not the full platform. Do not add features outside the scope below unless instructed later.

## Core product principles

The experience must be:

* Clean
* Calm
* Warm
* Uncluttered
* Mobile-first
* Easy for non-technical users
* Encouraging rather than guilt-driven
* Designed for transformation rather than maximum screen time

The app must feel like a thoughtful guided conversation, not a traditional learning-management system.

Use plain, natural language. Avoid corporate dashboard styling, excessive statistics, complex menus, gamified clutter, or long scrolling pages.

## Technical requirements

Build a responsive web application that works well on mobile phones.

Preferred stack:

* React
* TypeScript
* Tailwind CSS
* Firebase Authentication
* Cloud Firestore

Use a clean and maintainable component structure.

All journey and devotional content must load from Firestore or a clearly separated seed-data layer. Do not permanently hard-code devotional content directly into page components.

Create environment-variable placeholders for Firebase configuration.

Do not expose private keys or secrets in client code.

Include basic input validation, loading states, empty states, and error messages.

## Prototype scope

Build only the following:

1. Welcome and authentication
2. User onboarding
3. Feeling check-in
4. Four-tab mobile navigation
5. Walk home screen
6. Seven-day “15 Minutes with Jesus” journey
7. Journey progress tracking
8. One five-day sermon Companion Journey
9. Timestamped YouTube sermon links
10. Simple Personal page
11. Placeholder Bible and Journeys pages
12. Basic pastor/admin review interface

Do not build advanced gamification, complex reports, payments, subscriptions, multi-church support, events, volunteer management, or full AI chat yet.

## Main navigation

Create a persistent bottom navigation bar with four sections:

* Walk
* Bible
* Journeys
* Personal

The active tab must be clearly visible without using loud colours or oversized icons.

## Screen 3: Feeling check-in

After sign-in, ask:

“How are you feeling today?”

Display six rounded selectable cards:

* Hopeful
* Tired
* Struggling
* Nervous
* Afraid
* Okay

Save the selected feeling with the current date.

After selection, show a brief response that adapts to the feeling.

Examples:

Hopeful:
“It’s good to see you today. Let’s keep walking together.”

Tired:
“You don’t have to rush today. Let’s take one small step together.”

Struggling:
“I’m glad you came. We can take this one step at a time.”

Afraid:
“You’re not alone in what you’re carrying today. Let’s begin gently.”

Do not make the system claim to have feelings, pray independently, hear God’s voice, or speak prophetically.

Button:

* Let’s Begin

## Screen 4: Walk home

## Primary journey: 15 Minutes with Jesus

Create a seven-day journey.

Each day should load one step at a time rather than displaying one very long scrolling page.

Each day contains:

1. Today’s theme
2. Short mentor introduction
3. Scripture reference
4. Devotional reflection
5. Reflection question
6. Optional written response
7. Prayer prompt
8. Practical action step
9. Completion button

Use the completion message:

“Great job. See you tomorrow.”

The journey screen should feel conversational and spacious.

Do not place a large repeated Scripture block at the bottom.

Use realistic sample content that can later be replaced.

Create seven seed journey steps with these placeholder themes:

Day 1 — Jesus Meets You Here
Day 2 — You Are Not Alone
Day 3 — Learning to Trust
Day 4 — Listening to Jesus
Day 5 — Taking One Faithful Step
Day 6 — Walking with Others
Day 7 — Keep Walking

## Progress tracking

Store:

* Current journey
* Current day
* Completed steps
* Completion date
* Current streak
* Longest streak
* Last activity date

A missed day must not shame the user.

When someone returns after a break, display:

“Welcome back. We’re glad you’re here. Let’s take the next step together.”

Do not display language such as:

“You lost your streak.”

## Pastor/admin prototype

Create a protected route at:

/admin

For the prototype, support a simple admin role.

The admin interface should allow a pastor to:

* View journeys
* View the sermon record
* View the generated five-day Companion Journey
* Edit daily titles
* Edit devotional text
* Edit Scripture references
* Edit questions
* Edit prayer prompts
* Edit action steps
* Edit timestamps
* Preview the journey
* Change status between Draft, Approved, and Published

The system must never automatically publish AI-generated pastoral content.

The workflow is:

Draft
Pastoral Review
Approved
Published

Pastor-approved edits must not be overwritten by future regeneration.

## Design system

Use:

* Soft white or warm-neutral backgrounds
* Dark readable text
* One restrained accent colour
* Rounded cards
* Subtle borders
* Generous spacing
* Accessible font sizes
* Clear button hierarchy

Avoid:

* Neon colours
* Dark gaming interfaces
* Excessive gradients
* Dense dashboards
* Large blocks of statistics
* Cartoon imagery
* Competitive leaderboards
* Overuse of badges

The app should feel pastoral, contemporary, and trustworthy.

## Accessibility

Ensure:

* Good text contrast
* Large touch targets
* Keyboard accessibility
* Clear focus states
* Responsive typography
* Form labels
* Helpful validation messages
