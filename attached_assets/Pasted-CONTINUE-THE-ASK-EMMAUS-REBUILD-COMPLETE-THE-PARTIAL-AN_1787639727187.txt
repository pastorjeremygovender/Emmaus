PHASE 4 — COMPLETE DAILY RHYTHM ELIGIBILITY
==================================================

Preserve the server-side pre-context filtering already implemented.

Complete one shared Daily Rhythm eligibility service used by:

- Daily Rhythm opening
- Ask Emmaus retrieval
- Ask Emmaus recommendations
- Search
- canonical link validation

A Daily Rhythm is eligible only when:

1. It is the user’s currently unlocked Daily Rhythm; or
2. The user previously completed it; or
3. It is currently open and available to that user.

It is ineligible when:

- it is a future day
- it is locked
- the user has not reached it
- it belongs to another user’s progress
- it is unpublished
- the user otherwise lacks access

Do not rely on prompt instructions as the security mechanism.

Restricted Daily Rhythm content must be filtered before model context assembly and before search results or recommendations are created.

Test using actual database fixtures for:

- brand-new user
- today available but incomplete
- today completed
- several previously completed days
- future locked day
- another user’s progress
- unpublished Daily Rhythm

Tests must prove the restricted content itself never reaches model context—not merely that it is absent from the final wording.
