GATE 2: REMOVE THE 6.8–14.8 SECOND BLANK WAIT

The current strategy buffers the complete typed response until final normalization. This has fixed citation consistency but created unacceptable perceived latency.

Replace whole-answer buffering with safe incremental normalization.

Preferred approach:

1. Receive streamed model output server-side.
2. Buffer only until a complete safe textual unit—normally a sentence or paragraph—is available.
3. Normalize and validate Scripture and resource references in that unit.
4. Emit the validated unit immediately.
5. Continue for subsequent units.
6. Run the complete final answer through the full normalizer before persistence.
7. Ensure the final persisted `displayAnswer` is identical in meaning and canonical references to what was rendered.
8. Never emit a partial Markdown link, partial citation token, incomplete Bible reference or unvalidated resource action.

The streaming parser must safely handle:

* a Bible reference split across model chunks;
* numbered Bible books;
* verse ranges;
* punctuation after a reference;
* Markdown split across chunks;
* resource titles split across chunks;
* a sentence containing both Scripture and a sermon;
* malformed or unsupported references;
* the stream ending without final punctuation;
* model or retrieval failure midway through the response.

If sentence-level normalization cannot be implemented safely within the existing stream format, implement a structured citation-token stream in which the model may only refer to pre-resolved Scripture and resources using server-issued identifiers. Validate each token before emitting it.

Do not revert to unvalidated raw streaming.
