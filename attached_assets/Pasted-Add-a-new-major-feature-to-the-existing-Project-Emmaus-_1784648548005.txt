Add a new major feature to the existing Project Emmaus application called Emmaus Rooms.

This is a shared-journey feature.

Do not redesign the existing app.
Do not change authentication, current journeys, sermon companions, admin portal, Media Studio, Bible placeholder, reflections, prayer requests, or progress logic except where integration with Rooms is explicitly required.

Create a checkpoint before editing.

## Purpose

Rooms allow families, friends, couples, small groups and ministry teams to do selected journeys together while each person still retains a private personal walk.

The core principle is:

Private by default. Shared by choice.

A Room must never expose a member’s private reflections, private prayers, Bible notes, AI conversations or personal journal unless that person explicitly shares something.

## Locked journey-start wording

Before any journey begins, show this exact standardised screen:

How would you like to do this journey?

Option 1:

I’d like to do this alone

A private journey between you and Jesus.

Option 2:

I’d like to do this with others

Invite family, friends or a group to walk together.

Button:

Continue

Use this exact wording for every journey type.

Do not vary it by journey category.

Add a small reassurance below the options:

You can always invite others later.

## Personal journey behaviour

If the user selects:

I’d like to do this alone

start the journey through the existing personal journey flow.

Do not create a Room.

Do not alter existing personal progress.

## Shared journey behaviour

If the user selects:

I’d like to do this with others

show:

Who would you like to walk with?

Options:

- Choose an existing Room
- Create a new Room
- Join an existing Room

Do not show a public list of Rooms.

Do not allow Room search by name.

Do not allow users to browse or randomly join Rooms.

- Friends

- Other

- return the user to the shared journey flow

## Joining a Room

A person may join a Room only through one of these methods:

1. Invitation link
2. Access code

No other joining mechanism is allowed.

### Invitation link

Use a route such as:

/join-room/:inviteToken

When opened, show:

You’ve been invited to join

[Room Name]

Invited by:
[Owner or inviter name]

Room type:
[Type]

Buttons:

- Join Room
- Cancel

Validate:

- invite exists
- invite has not expired
- invite has not been revoked
- Room still exists
- user is not already a member

Do not add the person until they explicitly tap Join Room.

### Access code

Create a Join Existing Room page.

Fields:

- Room access code

Button:

Join Room

Before joining, show a confirmation screen with:

- Room name
- Room type
- inviter or owner
- member count

Then require:

Join Room

Do not join silently after code entry.

## Room roles

Use these roles:

Owner

Can:
- rename Room
- invite members
- revoke invitations
- remove members
- assign or remove Leaders
- start a shared journey invitation
- archive or delete Room

Leader

Can:
- invite members
- revoke invitations they created
- start a shared journey invitation
- moderate Room discussion where enabled

Cannot:
- delete Room
- remove Owner
- transfer ownership

Member

Can:
- view Room
- accept journey invitations
- participate in shared journeys
- view Room-level shared content
- leave Room

Cannot:
- change Room settings
- remove members
- assign roles

## Room privacy

Joining a Room must never expose:

- private journey reflections
- private prayer requests
- private Bible notes
- personal AI conversations
- private journal entries
- personal journeys not associated with the Room
- email addresses of other members unless current privacy settings already permit this

Room members may see only:

- display name
- optional profile image
- Room role
- shared journey participation
- completion state for a Room journey
- content explicitly shared with the Room

## Shared journey invitations

Do not create complex journey-specific membership management.

When a Room member starts a journey with a Room:

1. Create a shared journey invitation for that Room.
2. Notify or display the invitation to all current Room members.
3. Do not automatically enrol anyone except the person who starts it.
4. Every other Room member chooses individually whether to participate.

Show:

[Member Name] has invited [Room Name] to begin:

[Journey Title]

Buttons:

- Join Journey
- Maybe Later

If they choose Join Journey:

- create their own user journey progress record
- link that progress to the Room shared journey instance
- preserve independent personal progress
- start at Day 1 unless the product already supports another start rule

If they choose Maybe Later:

- do not enrol them
- keep the invitation accessible in the Room
- allow them to join later

Do not create separate admin-controlled membership lists for each journey.

## Leaving and removal

Members may leave a Room.

Require confirmation:

Leave this Room?

Leaving a Room must:

- remove Room membership
- stop access to Room discussion
- preserve the user’s personal journey progress
- preserve any personal reflections
- remove their Room-sharing permissions
- not delete the Room

Owners cannot leave until they:

- transfer ownership
or
- delete the Room

Removing a member must not delete that person’s personal journey data.

## Room deletion

Only the Owner may delete a Room.

Require strong confirmation:

Delete this Room permanently?

Deleting a Room must:

- archive or remove Room membership
- revoke active invitations
- stop new shared activity
- preserve each user’s personal journey progress and private content
- not delete journey definitions

Prefer soft deletion or archival where possible.

## Security requirements

Implement or prepare for these rules:

- only Room members can view a Room
- only Owner and Leader can invite
- only Owner can delete Room or transfer ownership
- users can only join through a valid invite or access code
- users can only edit or delete their own Room posts unless Owner or Leader moderates
- users control whether their reflection is shared
- Room membership never grants access to private user records
- ordinary users cannot modify Room roles directly
- access codes and invite tokens must not be predictable

Do not weaken existing application security.
