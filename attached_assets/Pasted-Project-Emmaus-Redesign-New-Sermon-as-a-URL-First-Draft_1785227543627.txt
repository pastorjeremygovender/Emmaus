Project Emmaus — Redesign New Sermon as a URL-First Draft Generator

Redesign the current New Sermon workflow so a pastor can paste a YouTube sermon URL and let Emmaus generate a complete editable sermon draft and companion devotional draft.

The pastor-facing experience should be simple:

Paste YouTube URL
→ Generate Draft
→ Review
→ Edit
→ Publish manually

Nothing may publish automatically.

Do not remove the ability to paste a transcript manually.
Do not generate content without an explicit button press.
Do not treat sermon companions as Journeys.
Do not expose technical IDs to the pastor.
Preserve the existing Emmaus Content Studio styling.

====================================================
1. NEW SERMON LANDING STATE
====================================================

Replace the current long blank form as the first thing the pastor sees.

The initial New Sermon screen should contain:

Heading:
Create Sermon Content

Supporting text:
Paste a YouTube sermon link and Emmaus will prepare an editable sermon record and companion devotional draft for your review.

Primary card:

YouTube URL

[ Paste YouTube link here ]

Primary button:

Generate Draft

Secondary divider:

or

Paste Transcript Instead

- title;
- speaker;
- date;
- series;
- Scripture reference;
- summary;
- topics;
- keywords;
- transcript status;
- companion ID.

These become editable fields after generation.

====================================================
3. GENERATION PIPELINE
====================================================

When Generate Draft is pressed for a YouTube URL, run the following server-side pipeline:

Step 1:
Validate and normalize the YouTube URL.

Support common formats including:

- youtube.com/watch?v=
- youtu.be/
- youtube.com/live/
- youtube.com/shorts/ where a valid transcript exists

Extract and store the canonical video ID.

Step 2:
Retrieve available video metadata:

- title;
- channel name;
- publication date;
- thumbnail URL;
- duration where available.

Step 3:
Retrieve the transcript or captions.

Prefer:

1. creator-provided captions;
2. manually uploaded captions;
3. auto-generated captions when available.

Step 4:
Normalize the transcript:

- preserve sermon order;
- remove duplicate caption fragments;
- remove unnecessary timestamps from the readable transcript;
- preserve timestamp mappings separately for future deep links;
- do not rewrite the sermon before analysis.

Step 5:
Analyse the sermon.

Step 6:
Generate an editable Sermon Draft.

Step 7:
Generate an editable Sermon Companion Draft.

Step 8:
Save both as Draft only.

Step 9:
Open the generated sermon review editor.

Do not publish either record automatically.

====================================================
4. FAILURE AND FALLBACK BEHAVIOUR
====================================================

If the transcript cannot be retrieved, do not fail with a raw technical error.

Show:

We couldn’t retrieve a transcript from this video.

You can paste the sermon transcript below and Emmaus will continue preparing the draft.

Provide:

[ Paste Transcript ]

[ Continue Generating Draft ]

Preserve the original YouTube URL and metadata already retrieved.

Do not make the pastor re-enter the URL.

Handle cleanly:

- invalid YouTube URL;
- private video;
- deleted video;
- captions disabled;
- no transcript;
- provider timeout;
- rate limiting;
- transcript too short;
- unsupported URL.

Never display:

- stack traces;
- provider response bodies;
- raw HTML;
- API keys;
- internal route names;
- “Cannot POST”;
- undefined or null.

====================================================
5. LOADING EXPERIENCE
====================================================

Suggested steps:

Retrieving sermon details
Retrieving transcript

Show one calm progress interface.

Do not use fake percentages unless the backend provides genuine progress.

Disable repeated submissions while generation is running.

Prevent duplicate sermon and companion records.

Provide a safe Cancel action only if cancellation is technically supported.

====================================================
7. SERMON ANALYSIS RULES
====================================================

Analyse the sermon as a pastoral message, not merely as a generic summary.

Identify:

- main Scripture;
- central Christ-centred message;
- primary pastoral concern;
- main teaching points;
- repeated ideas;
- important illustrations;
- warnings;
- encouragements;
- practical applications;
- closing invitation or response;
- supporting Scriptures actually mentioned.

Preserve Pastor Jeremy’s theological meaning and pastoral emphasis.

Do not replace strong biblical language with generic self-help.

Do not introduce theology that is not supported by the sermon.

Clearly distinguish the main Scripture from supporting references.

====================================================
8. COMPANION DEVOTIONAL DRAFT
====================================================

The generated companion is a Sermon Devotional, not a Journey.

Remove all pastor-facing references to:

Linked Companion Journey ID

Replace the current section with:

Sermon Companion

Fields:

Companion Title

Number of Days

Default:
5 days

Primary action:

Generate Companion Draft

When the initial URL generation succeeds, generate the companion automatically as part of the same draft-generation process.

The pastor may regenerate the companion separately after editing the sermon record.

Do not expose a technical companion ID in the main editor.

Use the real database relationship internally.

====================================================
9. COMPANION CONTENT STRUCTURE
====================================================

Generate five editable daily entries by default.

Each day must contain:

Day Number

Title

Scripture Reference

Greeting

Reflection

Prayer

Your Next Step

Closing

Status:
Draft

Each day should explore a distinct part of the sermon while remaining connected as one continuous weekly companion.

Do not create five repetitive summaries.

Suggested progression:

Day 1:
The central truth of the sermon

Day 2:
A key heart issue or obstacle

Day 3:
A deeper biblical truth

Day 4:
Practical response and obedience

Day 5:
Hope, commitment and continued faith

Adapt this progression to the actual sermon rather than forcing it mechanically.

====================================================
10. EMMAUS VOICE
====================================================

Generated devotionals must use the approved Emmaus voice:

- written to one person;
- warm and pastoral;
- clear enough for a new believer;
- Scripture-first;
- Jesus-centred;
- practical without becoming self-help;
- one paragraph per complete thought;
- mostly two to four sentences per paragraph;
- one practical next step;
- finish with hope.

Do not:

- shame;
- manipulate;
- exaggerate;
- use generic motivational clichés;
- invent personal stories;
- misquote the pastor;
- add unsupported claims;
- automatically publish.

Default closing:

Tomorrow we’ll continue reflecting on Sunday’s message together.

For the final day:

Keep walking in the truth God has shown you this week.

The pastor must be able to edit all wording.
