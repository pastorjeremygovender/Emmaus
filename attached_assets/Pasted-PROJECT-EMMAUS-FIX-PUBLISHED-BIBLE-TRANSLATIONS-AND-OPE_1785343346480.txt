====================================================
CHECK LOCAL BIBLE ASSETS
====================================================

Determine whether BSB, ASV and KJV are loaded from:

- JSON files
- bundled assets
- database records
- server filesystem
- an external Bible API

If they use local files, verify:

- the files are committed to Git;
- they are not excluded by .gitignore;
- production includes them in the build;
- import paths use exact filename capitalization;
- no Windows-only file paths are used;
- no development-only absolute paths are used;
- no runtime filesystem access depends on files unavailable in production;
- all filenames and folder names match Linux case sensitivity.

Pay particular attention to differences such as:

- BSB.json vs bsb.json
- KJV.json vs kjv.json
- ASV.json vs asv.json
- Luke.json vs luke.json

Production is case-sensitive even where the local environment may appear tolerant.

Use production-safe imports or asset paths.

====================================================
CHECK EXTERNAL API CONFIGURATION
====================================================

If these translations use an external Bible API, verify:

- production API key exists;
- the key is available to the correct server process;
- the key is not expected in browser-only code;
- the production endpoint URL is correct;
- translation IDs are correct;
- production requests are not blocked by CORS;
- the deployed origin is permitted;
- quota or provider errors are not being hidden.

Do not expose API secrets in browser code or logs.

====================================================
FAILURE HANDLING
====================================================

Do not show:

“Luke 1 is not available in this translation”

when the real cause is:

- missing production asset

====================================================
ISSUE 2 — MY BIBLE MUST OPEN AT THE TOP
====================================================

CURRENT BEHAVIOUR

When the user clicks My Bible from the bottom navigation, the page opens around the centre of the page.

EXPECTED BEHAVIOUR

Every normal navigation into My Bible must open at the top of the page.

This includes:

- clicking My Bible in bottom navigation
- opening the Bible home/library page
- opening a selected chapter from another screen
- switching to a new chapter
- switching translations where appropriate

Implement route-level scroll restoration.

On normal route navigation to My Bible or a new Bible chapter:

- scroll the main document or actual scroll container to top
- use immediate positioning unless smooth scrolling is already approved
- ensure it runs after the route/content has mounted
- do not scroll the wrong nested element

Check whether the application uses:

- window scrolling
- a custom main scroll container
- nested overflow panels
- preserved browser scroll state

Reset the correct scroll container.

====================================================
DO NOT BREAK INTENTIONAL RETURN POSITION
====================================================

If the user opens a temporary overlay or a note and then returns to the same Bible chapter, preserving their reading position may be useful.

Do not indiscriminately reset scroll for every state update.

Reset to top when:

- entering My Bible through bottom navigation
- opening a different book
- opening a different chapter
- navigating from another main section

Preserve reading position where appropriate when:

- closing Notes
- closing Save/bookmark controls
- returning from a temporary panel to the same chapter
