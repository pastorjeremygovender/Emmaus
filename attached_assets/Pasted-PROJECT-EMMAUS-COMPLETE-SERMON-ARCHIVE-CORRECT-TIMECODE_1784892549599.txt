==================================================

- caption text

- applause and transitions
- welcome and announcements

- existing metadata or manually verified start points

Store:

- videoStartSeconds = 0
- detectedSermonStartSeconds
- sermonStartConfidence
- sermonStartMethod

- preview the detected sermon start

- correct it manually
- mark it verified

Manual verification must override automatic detection.

Do not apply one universal 30-minute offset to every service.

PART 3 — CORRECT TIMESTAMP MODEL
==================================================

Audit the entire timestamp pipeline.

Each sermon segment must distinguish between:

1. sermon-relative time
2. absolute full-video time

Store both explicitly:

- relativeStartSeconds
- relativeEndSeconds
- absoluteStartSeconds
- absoluteEndSeconds

For full-service videos:

absoluteStartSeconds =
finalSermonStartSeconds + relativeStartSeconds

absoluteEndSeconds =
finalSermonStartSeconds + relativeEndSeconds

However, if downloaded YouTube captions already contain absolute video timestamps, do not add the sermon offset a second time.

Determine and store the transcript timing basis:

- absolute_video
- sermon_relative
- trimmed_audio_relative
- unknown

The system must normalise every segment exactly once.

Do not guess.
