==================================================
1. VALIDATE EVERY VOICE ACTION
==================================================

No transcription, language-model response or raw Voice command may directly:

- navigate
- open a resource
- retrieve restricted content
- begin playback
- seek within audio
- construct a route
- construct an audio URL
- execute a player command

All Voice actions must pass through the validated intent contract and canonical resource resolver.

Validate:

- intent type
- action
- canonical resource type
- canonical resource ID
- Bible book
- chapter
- verse or range
- publication status
- tenant
- user access
- Daily Rhythm eligibility
- route
- audio-source authorization
- autoplay permission

Clear, safe commands should execute immediately after validation.

Example:

“Please read John 3:16.”

Required:

transcription
→ structured READ_RESOURCE intent
→ canonical Bible validation
→ canonical text retrieval
→ authorised audio-source resolution
→ Read to Me player opens
→ autoplay begins

No additional user tap is required.

Reject or clarify:

- invalid Bible references
- invented resource IDs
- mismatched resource type and ID
- unpublished resources
- another tenant’s resources
- future Daily Rhythm content
- ambiguous resource requests
- model-generated application URLs
- model-generated audio URLs
- low-confidence navigation or playback actions

Ensure Voice uses the same permission and Daily Rhythm eligibility services as text Ask Emmaus.

Add tests proving restricted or invented actions cannot navigate or play.

- user ID
- translation
- canonical book
- chapter
- current verse

- current segment ID
- optional text offset
- provider type

For other resources, save:

- user ID
- resource type
- canonical resource ID
- parent resource ID where applicable
- Step/day/chapter
- section ID
- paragraph or segment ID
- provider type
- provider-specific playback time where useful
- updated timestamp
- completed status

Progress must update at safe intervals and on:

- pause
- stop
- close
- navigation away
- app backgrounding where supported
- playback completion
- provider change

Do not generate excessive database writes every few milliseconds.

“Continue reading where I stopped” must:

1. Load the current user’s most recent unfinished Read to Me session.
2. Validate that the resource still exists and remains accessible.
3. Apply Daily Rhythm eligibility again.
4. Restore the logical text position.
5. Resolve the currently available audio provider.
6. Resume from the matching verse, paragraph or segment.

This must continue to work if the source later changes between:

- ElevenLabs TTS
- recorded audio
- future dramatized Bible audio

If several recent unfinished sessions are equally plausible, ask one brief clarification.

Add visible options where appropriate:

- Resume reading
- Start again

Do not mark a Bible chapter, Daily Rhythm, Walk Step or devotional complete merely because audio started.

Use the existing completion rules for each resource.

3. SCREEN-OFF AND BACKGROUND PLAYBACK
==================================================

Complete the PWA’s technical background playback implementation using supported browser capabilities.

Use the existing audio player with Media Session integration where supported.

When a reading session is active:

- set the correct title
- set resource/chapter/verse information
- set artwork only where valid
- expose play
- expose pause
- expose previous
- expose next
- expose seek where supported
- keep player state synchronized with lock-screen controls

Audio should continue when:

- the installed PWA is backgrounded
- the screen locks

where the operating system and browser permit it.

The microphone must not remain active during ordinary screen-off playback.

Screen-off playback is not permission to implement continuous background listening.

Handle:

- incoming call interruption
- another app taking audio focus
- Bluetooth disconnection
- network interruption
- PWA returning to foreground
- page/component remount
- TTS segment boundary
- expired authorised audio URL
- playback-provider failure

When playback is interrupted:

- preserve logical reading position
- display Paused
- allow reliable resume
- do not unexpectedly restart from the beginning
- do not unexpectedly resume much later without user action

Ensure TTS is delivered through actual playable audio segments/streams compatible with background playback. Do not rely on a foreground-only browser speech-synthesis mechanism if it stops when the screen locks.
