URGENT CORRECTION TO THE PUBLISHED ASK EMMAUS UPDATE

The recently published Ask Emmaus update has caused important regressions.

Do not begin the Ask Emmaus Voice rebuild yet.

Correct and verify the current text-based Ask Emmaus experience first, because Voice must eventually inherit a reliable, personable, Scripture-first and church-specific Ask Emmaus system.

Create a checkpoint before making changes.

Do not roll back the security improvements, canonical Bible normalization, Daily Rhythm filtering, tenant isolation or server-side citation validation already implemented.

Correct the regressions below.

==================================================
1. RESTORE A PERSONABLE, RELATIONAL RESPONSE
==================================================

Ask Emmaus no longer acknowledges the user and simply begins delivering an answer. This feels impersonal and inconsistent with the purpose of Emmaus.

Restore relational acknowledgement.

Ask Emmaus should respond as a thoughtful discipleship companion within the user’s Local Church—not as a generic search engine or Bible-reference generator.

Use the authenticated user’s preferred display name when it is available.

For my administrator account, use:

“Pastor Jeremy”

Do not use:

- Pastor Govender
- Jeremy Govender
- the pastor
- the user
- a generic account label

However, do not mechanically begin every response with “Pastor Jeremy” or repeat the name throughout the answer.

Use natural judgement.

Examples:

For a personal or pastoral question:

“Pastor Jeremy, that is a difficult and deeply personal question.”

For a question expressing pain:

“I’m sorry you’re carrying this, Pastor Jeremy.”

For a straightforward Bible question:

“That’s an important question.”

For a follow-up question within an active conversation:

“Let’s look at that more closely.”

For a simple factual request:

Answer naturally without forcing an emotional acknowledgement.

The acknowledgement must relate to what the user actually asked.

Avoid repetitive stock openings such as:

- “That’s a great question.”
- “Thank you for asking.”
- “The Bible has much to say about this.”
- “I’m glad you asked.”

Do not falsely claim to understand feelings the user did not express.

Maintain conversational continuity. A follow-up answer should not sound as though a completely new conversation has begun.

==================================================
2. SCRIPTURE REFERENCES MUST BE CLICKABLE
==================================================

The updated answers now mention Scripture within paragraphs, but the references are not clickable.

This is a regression.

Scripture must remain naturally integrated into the written answer, but every validated Scripture reference must also be rendered as a working link.

Example answer text:

“Jesus describes eternal life as knowing the Father and knowing Him (John 17:3).”

In the rendered interface, “John 17:3” must be clickable.

Clicking it must:

- open My Bible
- open John
- open chapter 17
- scroll to verse 3
- highlight verse 3
- work in the browser
- work in the installed PWA
- survive page refresh
- preserve the destination through authentication

For a range such as John 3:16–18:

- open John 3
- scroll to verse 16
- highlight verses 16 through 18

For a chapter such as Psalm 23:

- open Psalm 23 at the beginning of the chapter

Do not require Scripture references to be removed from the paragraph and placed only in a separate list.

The preferred experience is:

1. Natural clickable references within the answer.
2. A small “Scripture” section below the answer when several passages are central to the response.

Do not turn every answer into a cluttered list of Bible links.

==================================================
3. DO NOT LET THE MODEL GENERATE RAW LINKS
==================================================

Preserve the safety rule that the language model must not invent URLs.

The model should return structured Scripture references alongside the answer.

Trusted application code must:

1. Validate the Bible book.
2. Validate the chapter.
3. Validate the verse or range.
4. Generate the canonical My Bible route.
5. Associate the validated structured reference with the matching visible reference in the prose.
6. Render it as a clickable component.
7. Omit link behaviour if validation fails.

Implement safe inline Scripture citation rendering.

Possible structured result:

{
  "answer": "Jesus describes eternal life as knowing the Father and knowing Him (John 17:3).",
  "scriptureReferences": [
    {
      "displayText": "John 17:3",
      "book": "John",
      "chapter": 17,
      "verseStart": 3,
      "verseEnd": 3
    }
  ]
}

The frontend must safely match and render the validated display reference as a clickable citation.

Do not allow arbitrary model-generated HTML.

Do not allow uncontrolled model-generated Markdown links.

If exact inline matching cannot be performed safely, render a validated clickable Scripture chip immediately after the relevant paragraph rather than silently leaving the citation unlinked.

==================================================

Ask Emmaus is not intended to be a generic Christian chatbot.

It is a Scripture-first, church-specific discipleship tool.

For the current ICC tenant, it must meaningfully draw upon relevant published content from Isipingo Community Church, including:

- Pastor Jeremy’s sermons
- sermon transcripts
- Sermon Companions
- Daily Devotionals

- eligible Daily Rhythm content
- other published ICC discipleship resources

The priority must remain:

Scripture is authoritative.

Local church content helps explain, reinforce and apply Scripture within the life and teaching of the user’s church.

Do not treat local resources as equal to Scripture.

Do not reduce church-specific retrieval to occasional recommendation cards at the end. When a relevant ICC resource exists, its insight should inform the substance of the answer.

==================================================

For every substantive Ask Emmaus question:

STAGE 1

Retrieve relevant Scripture.

STAGE 2

Search eligible published content belonging to the current tenant/church.

This second retrieval stage must run consistently—not only when particular keywords such as “sermon” or “Pastor Jeremy” appear in the question.

Search across all supported ICC resource types.

- incorporate its insight naturally
- identify the source honestly
