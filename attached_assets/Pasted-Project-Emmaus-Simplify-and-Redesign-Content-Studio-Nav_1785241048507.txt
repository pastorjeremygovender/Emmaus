Project Emmaus — Simplify and Redesign Content Studio Navigation

The current Content Studio has become too complicated.

There are too many top-level areas, overlapping concepts and administrative screens that do not help Pastor Jeremy create and publish content efficiently.

Simplify Content Studio around the actual Emmaus content workflow.

This is a focused information-architecture and navigation redesign.

Do not change member-facing navigation.
Do not change the underlying content types or progress systems.
Do not merge Daily Devotionals, Journeys or Sermon Companions.
Do not delete content records.
Do not rebuild working editors unnecessarily.

====================================================
PRIMARY GOAL
====================================================

Content Studio should contain only these five top-level tabs:

1. Daily Rhythm
2. Daily Devotionals
3. Journeys
4. Sermon Companions
5. Media Studio

Remove the current Overview tab and dashboard in its existing form.

Remove standalone top-level tabs that are now included elsewhere.

The new Content Studio should feel simple enough that a pastor immediately knows where to go.

====================================================
LOCKED TOP-LEVEL NAVIGATION
====================================================

Use this exact order and terminology:

Daily Rhythm

Daily Devotionals

Journeys

Sermon Companions

Media Studio

Do not show these as separate top-level Content Studio tabs:

- Overview
- Collections
- Sermons
- YouTube Archive
- Media

Collections must live inside Journeys.

Sermons and their companion content must live inside Sermon Companions.

YouTube Archive must live inside Media Studio.

====================================================
1. REMOVE THE CURRENT OVERVIEW
====================================================

Remove Overview from the Content Studio top navigation.

Remove the current Overview screen containing:

- total counts;
- published counts;
- draft counts;
- collection counts;
- quick cards;
- recently updated;
- duplicated navigation links.

Do not redirect users to a blank Overview route.

When Content Studio opens, default directly to:

Daily Rhythm

Use the existing Daily Rhythm route where possible.

Old Overview URLs should safely redirect to Daily Rhythm.

====================================================
2. DAILY RHYTHM
====================================================

Daily Rhythm opens directly to:

10 Minutes with Jesus

Show:

- title;
- short description;
- existing day list;
- published/draft state;
- Add Day where valid;
- Development Mode controls where already supported.

Do not introduce collections or multiple Daily Rhythm tracks.

There remains only one Daily Rhythm:

10 Minutes with Jesus

Preserve:

- working editor;
- live preview;
- embedded Scripture;
- personalised greeting;
- publication workflow;
- Previous Days;
- calendar locking;
- Development Mode;
- completion and replay rules.

====================================================
3. DAILY DEVOTIONALS
====================================================

Daily Devotionals opens directly to the existing devotional-series list.

Show:

- series title;
- series type;
- status;
- published-entry count;
- total-entry count;
- Edit;
- Publish/Unpublish where supported;
- Delete.

Primary action:

+ New Series

Selecting a series opens its entry list and editor.

Do not place Daily Devotionals under Journeys.

Preserve:

- separate progress;
- member discovery;
- active-series selection;
- calendar locking;
- live preview;
- existing publication rules.

====================================================
4. JOURNEYS
====================================================

Journeys becomes one top-level area with two internal subtabs:

Collections

Standalone

Use these exact labels.

Default subtab:

Collections

----------------------------------------------------
JOURNEYS — COLLECTIONS
----------------------------------------------------

Collections contains grouped Journey pathways.

Examples:

New to Faith

Growing in Faith

Bible Studies

Christian Living

Opening a Collection displays the Journeys inside it.

Hierarchy:

Collection
→ Journey
→ Days

Actions:

+ New Collection

Inside a Collection:

+ New Journey

Inside a Journey:

+ Add Day

Do not expose Collections as a separate top-level Content Studio area.

----------------------------------------------------
JOURNEYS — STANDALONE
----------------------------------------------------

Standalone contains Journeys that do not belong to a Collection.

Use this for content that is intentionally independent.

Primary action:

+ New Standalone Journey

A Standalone Journey still contains Days and uses normal Journey progress.

Do not create a second Journey architecture.

Use the same Journey entity with a nullable collectionId or the project’s established equivalent.

----------------------------------------------------
JOURNEY CLASSIFICATION
----------------------------------------------------

Journey Type may still distinguish:

- Standard Journey;
- Bible Study;
- Foundations;
- Topical;
- other existing types.

This is metadata, not another top-level Content Studio tab.

Member-facing Next Steps may group Bible Studies separately even though they share Journey infrastructure internally.

====================================================
5. SERMON COMPANIONS
====================================================

Rename the current top-level Sermons area to:

Sermon Companions

This area manages both:

- the source Sermon;
- the generated Companion.

Do not separate these into competing top-level sections.

The default list should focus on the companion workflow.

Recommended columns or card information:

- Sermon title;
- speaker;
- sermon date;
- main Scripture;
- transcript status;
- sermon detection status;
- companion status;
- current-week status;
- actions.

Primary action:

+ New Sermon Companion

This opens the existing URL-first generation workflow:

Paste YouTube URL
→ detect sermon boundaries
→ confirm sermon section
→ generate source Sermon draft
→ generate five-day Companion draft
→ pastoral review
→ explicit publishing

Preserve separate Sermon and Companion records internally.

Do not store companions as Journeys.

----------------------------------------------------
SERMON COMPANION INTERNAL VIEWS
----------------------------------------------------

Inside a Sermon Companion record, use two subtabs:

Sermon Source

Companion

Sermon Source contains:

- YouTube URL;
- metadata;
- full service transcript;
- sermon-only transcript;
- sermon boundaries;
- sermon title;
- speaker;
- date;
- Scriptures;
- summary;
- central message;
- key truths.

Companion contains:

- companion title;
- companion status;
- current-week setting;
- daily entry tabs/list;
- editor;
- live preview;
- publication controls.

Do not expose technical relationship IDs.

----------------------------------------------------
CURRENT WEEK
----------------------------------------------------

Provide one clear action:

Set as This Week’s Sermon

Only one published Sermon Companion may be current at a time.

Preserve previous content and member progress when the current companion changes.

YOUTUBE ARCHIVE

- thumbnails;

- generated visual assets where supported.

Do not add advanced media-production features in this sprint.

This task is only to consolidate existing Media functionality under Media Studio.
