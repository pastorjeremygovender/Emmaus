PROJECT EMMAUS — SIMPLIFY WALK CARD NAVIGATION AND LESSON COMPLETION FLOW

The published app is working.

Create a checkpoint first:

PRE-WALK-CARD-AND-COMPLETION-FLOW-FIX

This task applies only to the user-facing Journey/Walk flow.

Do not modify:

- Journey authoring
- Rooms
- Today’s Steps
- Active Engagement architecture
- Daily Rhythm
- Daily Devotionals
- Sermon Companions
- Bible
- database schema

Do not create a migration.

====================================================
1. MAKE THE WHOLE WALK CARD CLICKABLE
====================================================

On the Coming to Jesus Journey page, the Walk card currently shows:

What went wrong
Description
5 Days · Self-paced
Continue
Bookmark
Details

Remove the Continue button from this card.

Make the main Walk card area clickable.

Clicking anywhere on the main card should open the What went wrong Walk overview page.

The Walk overview is the screen that displays:

- Walk title and description
- Journey information
- progress indicator
- current step
- Continue button
- complete lesson list
- completed lesson indicators

This is the correct destination.

The user should not have to choose between clicking the card and clicking Continue.

====================================================
2. PRESERVE SECONDARY CONTROLS
====================================================

Bookmark and Details may remain if they are still required.

Their clicks must not trigger the main card navigation.

Use event handling so:

- clicking the main card opens the Walk overview;
- clicking Bookmark only bookmarks;
- clicking Details only opens Details.

Do not place another Continue button on the outer Walk card.

====================================================
3. WALK OVERVIEW CONTINUE BUTTON
====================================================

Keep the Continue button on the What went wrong Walk overview page.

That is the correct place for Continue.

It should:

- open the next unfinished lesson;
- use the user’s saved progress;
- open the first published lesson when no progress exists;
- disappear when all required lessons are complete.

Do not change the current working lesson-opening behaviour.

====================================================
4. LESSON COMPLETION CONFIRMATION
====================================================

The current lesson-completion confirmation opens as a separate full screen.

The confirmation content itself is acceptable, but the navigation flow is inconsistent with other Emmaus content.

After the user taps:

Complete Today

show the approved completion confirmation briefly within the existing lesson flow or as a lightweight completion state.

Then the primary action should be:

Back to Walk

not:

Back to Next Steps

The destination must be the What went wrong Walk overview page.

====================================================
5. RETURN TO THE WALK OVERVIEW
====================================================

After completing any lesson, return the user to the What went wrong overview showing:

- updated progress;
- the completed lesson marked Done;
- the next unfinished lesson;
- the complete lesson list;
- Continue pointing to the next unfinished lesson.

Example:

Complete Day 3
→ confirmation
→ Back to Walk
→ What went wrong overview
→ Step 4 of 5
→ lesson list visible
→ Continue opens Step 4

Do not return directly to:

- Next Steps;
- Coming to Jesus collection page;
- a standalone completion dead end.

====================================================
6. PREVIOUS STEPS
====================================================

The completion confirmation may retain:

View Previous Steps →

This should open the previous/completed lessons for the same Walk.

It must not replace access to the Walk overview.

====================================================
7. BACK NAVIGATION
====================================================

Required navigation hierarchy:

Next Steps
→ Coming to Jesus
→ What went wrong overview
→ Lesson
→ Completion confirmation
→ What went wrong overview

Back from a lesson:

→ What went wrong overview

Back from the Walk overview:

→ Coming to Jesus

Back from Coming to Jesus:

→ Next Steps Journeys tab

Do not use generic browser-history navigation where it produces inconsistent destinations.

====================================================
8. CARD ACCESSIBILITY
====================================================

Because the full Walk card becomes clickable:

- use the correct button/link semantics;
- support keyboard activation on desktop;
- include a clear accessible label such as:
  “Open What went wrong”;
- preserve visible focus styling;
- do not create nested invalid interactive HTML.

Bookmark and Details must remain independently accessible.
